SafeFileDrag 手动测试页

地址：
本页的 window 日志监听器只写日志、从不调用 preventDefault()，因此不会影响扩展的判定。 每块的判定标准写在块内。

1. 空白区（完全没有监听器）

把本地文件拖到这里。

期望：页面无任何反应，也不导航。

2. <input type="file">

把本地文件拖到下面的输入框上（不是这块空白处）。

期望：文件名出现在这里（原生默认动作生效）。

3. 自定义 dropzone（dragover + drop 均 preventDefault）

拖入文件，边框会高亮。

期望：显示文件名。

4. 只监听 drop 的 dropzone

没有任何 dragover 监听器（扩展需要放行/补齐 dragover 才能让 drop 触发）。

期望：drop 触发并显示文件名，同时不导航。

5. 只监听 dragover（取消了 dragover，但不处理 drop）

把文件拖到这里再松手。

期望：什么都不发生，不导航。

6. contenteditable

在这里拖入一段选中的文本（应当正常插入）；也把本地文件拖进来（应当不导航）。

期望：文本正常插入；文件拖入无反应。

7. textarea（文本拖放）

期望：文本拖放不受影响。

8. 链接 / 图片拖放

从这里把链接拖到上面的 contenteditable 或 textarea：example.com

期望：链接 URL 正常插入，扩展完全不介入。

9. Web Component（open shadow root 里的 <input type="file">）

把文件拖到下面的输入框上（不是这块空白处）。

期望：文件名出现在这里。注意日志里 window drop 那行的 target 是宿主 div，而 composedPath[0] 才是真正的输入框—— 扩展必须看后者，否则会误拦合法上传。
